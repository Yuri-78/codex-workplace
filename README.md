# 序工 · 小型汽配制造与贸易 ERP

面向约 20 名员工、4 位系统使用者的第一版可运行系统。流程为 **订单 → 备料 → 一次成品入库 → 发货 → 月度对账 → 开票与收款**，不管理生产工单或工序。贸易业务采用买断再销售、赚差价的模式。

中文浏览器界面，Python 3.12+、SQLite、原生 JavaScript，无第三方运行依赖。当前属于业务验证版，应先用演示账套核对企业实际流程，再决定上线范围。

## Windows 本机试用（不需要服务器）

1. [下载 Windows 试用源码 ZIP](https://github.com/Yuri-78/codex-workplace/archive/refs/heads/erp-trial.zip)，右键“全部解压缩”。私有仓库需要先登录有权限的 GitHub 账号。
2. 安装 [Python 3.12 或更新版本](https://www.python.org/downloads/windows/)，安装时勾选 **Add python.exe to PATH**。
3. 打开解压后的目录，双击 **`start-windows.bat`**。

它会启动独立的 `.data/windows-demo` 演示账套，自动打开浏览器；首次启动时还会在 Windows 中打开本机生成的初始账号文件。浏览器默认使用本机端口 8000，端口被其他程序占用时会选择空闲端口；以启动窗口显示为准。停止服务按 Ctrl+C，再次双击继续试用。

详细步骤见 `WINDOWS-TRIAL.txt`。该入口不需要安装 npm/pip 依赖，不提供公网访问，不会使用或修改正式账套，也不会把密码放进分发包。程序必须运行，不能直接用浏览器打开 `static/index.html`。Windows 批处理启动本身需在 Windows 上确认，本仓库的业务和浏览器测试在 Linux Chromium 下运行。

## 启动

在已有 checkout 中工作；云任务已隔离，无需额外建立 Git worktree。

```bash
cd /workspace/codex-workplace
# 体验演示账套（含虚构资料、期初库存和销售订单）
python3 server.py --demo --data-dir .data/demo --port 8000
```

服务默认仅监听本机 `127.0.0.1:8000`。健康检查：

```bash
curl --fail http://127.0.0.1:8000/api/health
```

创建独立空白账套，请使用另一数据目录，并且不加 `--demo`：

```bash
python3 server.py --data-dir .data/company --port 8000
```

同一端口只能运行一个服务，先停止原服务。演示和正式数据互不共享，切勿把演示数据当作真实库存。首次启动会初始化数据库及四个随机密码账号：

| 账号 | 人员建议 | 可执行的操作 |
| --- | --- | --- |
| admin | 老板 / 管理员 | 全部业务、物料资料和 BOM |
| sales | 业务人员 | 客户、供应商、销售、采购、收付款 |
| warehouse | 仓库人员 | 期初建账、收货、发货 |
| production | 备料与成品人员 | 查看备料需求、登记一次成品入库；旧账号登录名不变 |

初始密码仅保存在所选数据目录的 `initial-accounts.txt` 中，权限为仅文件所有者可读写；服务日志不会打印密码。由管理员安全分发，首次登录后使用右上角“修改密码”。密码变更会使该账号所有会话失效，旧密码文件不自动更新。所有账号目前都可查看经营数据，权限控制的是写入操作，不提供财务数据隔离。

企业内网使用可指定 `--host 0.0.0.0`，需自行配置网络访问权限。正式部署应使用有 TLS 的反向代理，并加 `--secure-cookie`，配置进程守护、持久化数据目录和定时异机备份。内置 HTTP 服务供开发与小规模验证使用，本仓库没有自动部署到公网。

## 已实现的业务流程

### 订单备料与自产成品

1. 录入客户、供应商、原材料及成品，维护“物料用量表”：每 1 单位成品所需的原料数量。例如每件用 1.25 米面料、4 米背胶。
2. 通过期初入库登记上线前的真实库存，业务人员创建销售订单。
3. “备料管理”按交期再按订单 ID 依次抵扣已入库成品，同一份库存只抵扣一次；不足部分按用量表换算原料，共用原料合并计算需求。贸易商品直接计算商品数量缺口。
4. **备料只看已入库实物库存，没有在途采购功能。** 待收货采购不抵扣缺口；实际收货后库存与备料测算更新。建议采购量只覆盖订单缺口，不额外加安全库存缓冲。
5. 备料看板不预留或扣减库存。查看、刷新和调整用量表不会改变库存；缺少用量表的成品会明确提示，不猜测原料需求。
6. 自产成品做好后，只点击一次“登记成品入库”：填写成品、数量、日期及加工费用（可填 0）。系统在同一事务中按当前用量表扣原料、计算成本并增加成品库存。原料不足或输入无效时全部回滚。
7. 仓库按销售单发货。系统不再新建生产工单，不提供单独领料、工序、报工和生产成本页；实际消耗与入库成本可从库存流水、成品入库记录查询。
8. 历史生产数据保存在数据库和备份中。旧版已经扣料但尚未入库的记录会作为“历史已备料待入库”提示，先单独抵扣需求，再选择原记录办理入库，不重新扣料。同一成品有此类历史记录时会阻止普通入库，避免误扣两次。

### 代理贸易（买断再销售）

1. 录入“贸易商品”，创建供应商采购单。
2. 仓库确认收货并登记采购成本。
3. 创建该贸易商品的销售订单，直接发货，无需物料用量表或成品入库。
4. 登记采购付款、销售收款；“收支与成本”分别汇总自产产品与代理贸易的已发货毛利。

### 库存及成本口径

- 单仓库；货币人民币；金额支持 2 位小数，数量支持 3 位小数，经营日期按北京时间处理。
- 数量以千分单位整数、金额以分存储；用料需求向上取到千分单位。
- 材料按实际入库成本、先进先出计算。成品单位成本 =（材料成本 + 手工登记的加工费用）÷ 入库数量，保留至分；会有舍入差异。
- 销售毛利 = 已发货销售金额 − 实际出库成本，未计税费与其他经营费用；属于管理口径，不是财务净利润。
- “销售 / 采购未结余额”按所有订单合同金额扣减已登记收付款，**包含尚未发货 / 收货的订单**，不是按发票确认的会计应收应付。
- 库存仅由期初入库、采购收货、成品用料、成品入库和销售发货变动。数据库事务防止重复收货、重复发货和并发超卖。
- “库存管理”仅展示库存余额及出入库流水，不提供批次查询、追溯入口，也不要求手动填写批号。历史批次字段和每次入库的成本记录保留在数据库中，继续按入库先后顺序计价，不会因界面简化而重算或清除库存。
- 业务动作记录操作人、时间和单据编号；不提供删除或直接改库存的功能。

## 第一版边界

当前每张销售 / 采购单只有一个物料行，整单收货、整单发货、按实际完成数量登记成品入库；需要分批可先拆单。不提供库存预留、多仓库、盘点调整、退料、销售 / 采购退货、报废、返工、部分合格入库、订单取消与冲销、物料用量表删除与版本审批、物料资料编辑、发票和总账核算、Excel 导入导出、自动排产、扫码或设备联网。

系统不记录生产过程，成品入库代表人工确认对应成品可用，不包含产能、工时报工或检验指标。演示资料不是企业的真实产品。正式投入业务前，应先确定退货、损耗和库存调整流程，以及资料录错后的更正机制，再扩展功能。

## 备份与恢复

使用 SQLite 在线备份接口，不能在服务运行时只复制 `.sqlite3` 文件而遗漏 WAL。以下命令不会覆盖已有备份：

```bash
mkdir -p .data/backups
python3 backup.py .data/company/erp.sqlite3 .data/backups/company-2026-11-01.sqlite3
```

备份包含账号密码哈希和全部业务数据，须限制访问并定期保存到另一台机器；备份会清除登录会话，恢复后需重新登录。云环境快照不能代替业务定时备份。

恢复时先停止服务，将备份复制到一个**新的空目录**并命名为 `erp.sqlite3`，再将 `--data-dir` 指向该目录启动。不要覆盖正在使用的数据库，也不要把旧目录的 `-wal`、`-shm` 文件混进新目录。新目录启动会保留备份中的账号和密码，不会生成新账号文件。先核对余额、工单和库存流水，再切换使用。

## 账号说明和手机端使用

账号帮助已内置在网站 `/help` 页面；登录页面点“账号与手机使用帮助”，无需登录即可阅读。聊天中的 `/workspace/...` 文件链接并非网站地址，打不开时不用重复点击。

账号分别是：`admin`（管理员）、`sales`（业务）、`warehouse`（仓库）、`production`（生产）。四个账号没有通用密码；由部署管理员从对应账套的数据目录安全分发初始密码。若密码已丢失，服务器管理员可在交互式终端重置，不需要提供旧密码，也不会改变业务数据：

```bash
cd /workspace/codex-workplace
python3 manage_accounts.py --data-dir .data/company reset admin
```

新密码只通过终端隐藏输入，不能通过命令行参数、聊天或管道传入。该操作会使指定账号全部会话失效并记入日志；不影响其他账号会话。请选对数据目录，工具不会创建新数据库。示例 `company` 是正式账套目录；演示账套使用 `.data/demo`。

手机端的订单、工单、库存、成本表会显示为卡片，按钮适合触摸操作；权限及业务检查与电脑端相同。Android Chrome 或 iPhone Safari 可通过浏览器菜单“添加到主屏幕”，仍需联网使用，不支持离线录单。主屏幕入口及安装提示的可用性取决于浏览器和 HTTPS 配置。

### 公司与外出都使用的部署建议

推荐阿里云或腾讯云入门云服务器，初期可从 **2 核 / 4GB 内存、40GB 以上持久化磁盘** 起步，四个人共用一套数据库；是否需要升级应以实际业务数据及使用情况验证。另购一个域名，配置 HTTPS 反向代理、仅开放必要入口、进程守护和每日异机备份。公网访问 ERP 时服务端使用 `--secure-cookie`，只允许通过 HTTPS 登录。

公司 Wi-Fi 和手机流量都通过**同一个 HTTPS 域名**访问，避免建立两套账而不同步。中国内地服务器的域名通常需按服务商要求备案；购买前确认所在地区的备案和网络要求。这里不承诺具体价格或免费额度。

云环境“发布”只是发布开发环境版本，**没有自动购买服务器、注册域名或发布 ERP 网站**。目前还没有可供手机访问的公网 ERP 网址。本轮仅准备代码和本地验证；实际部署需确定服务器、域名和受支持的安全管理访问方式，不要在聊天中发送密码或密钥。

## 发票、收发货单与照片

“发票记录”区分 **开出的发票（收款）** 和 **收到的发票（付款）**，记录开票日期、发票单号、开票金额（价税合计）、税额、零件名称、计划收款 / 付款日期、实际收付款及结算状态。新发票不要求关联订单，可从同一客户的发货单中多选关联；收票可独立登记。发货关联不自动分摊金额或判断每张发货单的剩余开票额度。

- 新记录需填写零件名称和计划日期；关联发货单时可带入零件名称，多种零件可用逗号分隔。旧记录保留，未知计划日期显示“未填写”，可在“修改计划”中补充。
- 按零件名称和起止日期筛选，包含起止当天。发票可选择按开票日期、计划收付款日期或最近收付款日期筛选，并可筛选未收 / 部分收 / 已收、未付 / 部分付 / 已付。日期区间也适用于收货与出货工作区。
- “登记收款 / 付款”支持分次结算，状态按已结金额自动计算；“收付款明细”保留每次实际日期、金额和经办人。不能超出发票未结余额。
- 如旧版已经登记过同一订单的收付款，可在发票结算中选择关联已有整笔流水，避免重复新增。旧流水不会被猜测分配给发票；当前不支持把一笔旧流水拆分到多张发票。
- 原订单关联只对历史记录及兼容 API 保留；旧版订单结算页仍按订单流水计算。**新版主要以发票记录的未结余额跟踪结算**，不会根据发货关系推算订单收付款。
- 发票登记不改变库存或管理口径毛利；明确登记收付款时才产生资金流水。作废只标记本系统记录，不等于税务平台作废；有已关联收付款的发票不能直接作废。当前没有收付款冲销、红字发票、税务开票、验真或抵扣申报。
- 收货和出货记录保留对应单据、日期及经办人；目前仍为整单收发。历史单据补录不再次变动库存。
- 收货单和发货单的“照片”按钮可预览原图。管理员、仓库账号可拍照或选择本地照片，每次上传一张，每张单据最多 **10 张**、每张最大 **8 MB**，支持 JPG、PNG、WebP，暂不支持 HEIC、SVG、PDF、删除或替换附件。电脑选择本地图片；能否直接拍照取决于设备和浏览器。
- 照片作为 BLOB 保存在 SQLite 数据库中，手动、月度自动备份都会包含照片；查看原图也需要登录。照片不进入 Git，不通过公共文件目录开放。程序不自动压缩图片，照片和历史备份会占用更多磁盘空间。

## 升级本机已有试用账套

1. 停止 Spyder 中正在运行的程序，重启其控制台内核，避免 Python 继续使用旧版已导入模块。
2. **先把原程序整个目录复制到另一位置留底**，确保包含 `.data` 目录；不要在程序运行时仅复制 SQLite 主文件。
3. 下载新版 ZIP，把新版程序文件更新到原程序目录，**保留原 `.data` 目录**。新 ZIP 不包含数据库或初始密码；直接换到全新目录启动会创建另一份演示账套，不是原数据丢失。
4. 重新打开并运行 `try_erp.py`。本次数据库首次升级前会在同一账套的 `backups/` 下保存旧库备份。升级后保留原账号、密码、库存及单据。
5. 原有程序不支持新版结构；更新后不要再用旧程序操作新版数据库。若需要回退，停止服务后在独立目录中使用旧程序和旧备份，切勿覆盖正在使用的账套。

## 数据容量、安全和丢失风险

**尚未进行容量压测，没有经验证的最大订单量、数据量或并发人数承诺。** 当前提供 4 个固定角色账号；SQLite 会串行处理写入。系统未设置单据总条数上限，但页面每次读取全部业务数据，条数增多后可能出现加载变慢或占用较大内存。实际容量受电脑、磁盘、网络、记录数和并发操作影响。不能以 SQLite 的理论文件容量替代本系统的可用容量验证；长期大数据量使用前应增加分页并做代表性压测。

现有保护包括事务、外键、关键唯一约束、负库存检查、参数化 SQL、密码 scrypt 哈希、会话有效期、操作权限和基本操作日志。本版本显式使用 `synchronous=FULL` 并配合 WAL；正常关闭后已提交的数据保存在磁盘，不依赖 Spyder 或浏览器保持打开。它们可以降低操作冲突及异常中断风险，不能保证硬件故障、恶意修改、程序缺陷或误删下永不丢失。

数据库文件及备份**没有文件级加密**，拥有电脑文件读取权限的人可能读取业务数据。四个账号均可查看全部业务资料，日志也不是不可篡改审计系统。默认本机监听减少了外部暴露；公网使用另需 HTTPS、受控入口、权限与运维配置。本机文件权限设置不能代替 Windows 账户权限和磁盘保护。

管理员可点击右上角 **“备份数据库”** 下载一致的独立 SQLite 备份文件。备份清除旧登录会话，并校验数据库完整性；实际下载文件已进行恢复读取测试。只有管理员可以下载，备份包含业务资料及账号哈希，应限制访问并确认浏览器确实完成下载。恢复方法见前面的“备份与恢复”。

**当前有每月自动备份及升级前备份，但默认都保存在同一电脑；没有自动每日备份、异机同步或高可用机制。** 建议每天收工时下载一份备份保存到公司受控的另一台设备或存储，并定期在独立目录试恢复。最近一次备份之后的新数据，在设备损坏等情况下仍可能丢失。不要删除 `.data`、不要把运行中的数据库放在网盘同步目录或网络共享盘供多人直接写入。

## 每月自动备份

程序运行时每分钟自动检查一次，按**北京时间自然月**保存一份完整数据库快照。首次升级运行会立即为当前月份生成第一份；进入新月份后首次检查时生成新快照，同月已有快照不会被替换。备份使用一致的 SQLite 在线备份接口，清除旧登录会话，并进行完整性检查；生成完成后才以正式文件名发布。

默认位置是账套目录下的 `backups/monthly/erp-YYYY-MM.sqlite3`。例如 Windows 试用版在 `.data/windows-demo/backups/monthly/`。系统不自动删除旧备份，也不自动上传到云端；管理员在“发票记录”顶部可看到备份位置、最近月份及失败原因，点击“刷新”更新状态。

**关闭 Spyder、关闭程序、电脑关机时不能执行备份。** 下次启动只为当前月份补做，不会伪造停机期间其他月份的历史快照。没有安装 Windows 计划任务或常驻系统服务。如果要求程序关闭时也按时执行，需要另行配置系统级计划任务。

月度快照只能恢复到创建快照时的状态，之后的新数据在故障时仍可能丢失；同盘备份不能应对整块硬盘损坏。重要业务变更后仍可点击“备份数据库”，并把备份另存到受控的其他设备或存储。备份包含照片和账号哈希，没有文件级加密，请限制访问并定期在独立目录验证恢复。

## 客户月度对账

进入“月度对账”，选择客户及起止日期（含当天）生成对账单。系统只收集尚未进入其他对账单的发货记录，并保存零件、数量、订单单价和金额快照；每张发货单只计入一份对账单。晚补录的发货可在同一日期范围生成另一份补充对账单。

查看明细并打印或另存 PDF 后，人工与客户核对。确认无误后点“确认对账”，再点“登记发票”，带入同一客户尚未关联有效发票的发货单及金额；开票前仍需核对实际发票金额、税额及计划收款日期。不会自动向客户发送消息，不会自动在税务平台开票。

对账单使用保存时的价格快照，不随之后订单资料改变。目前不支持删除、反确认或修订已保存对账单。已有发票与发货的关系只表示关联，不自动分摊金额或判定是否足额开票；部分开票需在发票页面人工核对并继续登记。

## 库存管理简化

菜单由“库存与批次”改为“库存管理”，仅保留“库存余额”和“库存流水”。期初入库、采购收货和成品入库不再填写批号，成品入库记录及发货记录也不展示批次。底层自动生成内部库存标识以保持每次入库成本、先进先出及历史流水一致；旧客户端显式传入的批号仍兼容，但新版界面不使用它。

当前入库表单会携带一次性请求标识，同一表单的相同提交重试不会重复增加库存或扣原料；若实际要录入另一笔入库，应重新打开表单。网络失败时仍请刷新记录核对结果，不要未经核对重新录入同一笔实物。
