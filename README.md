# 序工 · 小型汽配制造与贸易 ERP

面向约 20 名员工、4 位系统使用者的第一版可运行系统。按订单生产为主，兼顾备货；生产工序默认为 **模切 → 缝纫 → 背胶 → 检验**。贸易业务采用买断再销售、赚差价的模式。

中文浏览器界面，Python 3.12+、SQLite、原生 JavaScript，无第三方运行依赖。当前属于业务验证版，应先用演示账套核对企业实际流程，再决定上线范围。

## Windows 本机试用（不需要服务器）

1. [下载 Windows 试用源码 ZIP](https://github.com/Yuri-78/codex-workplace/archive/refs/heads/erp-trial.zip)，右键“全部解压缩”。私有仓库需要先登录有权限的 GitHub 账号。
2. 安装 [Python 3.12 或更新版本](https://www.python.org/downloads/windows/)，安装时勾选 **Add python.exe to PATH**。
3. 打开解压后的目录，双击 **`start-windows.bat`**。

它会启动独立的 `.data/windows-demo` 演示账套，自动打开浏览器；首次启动时还会在 Windows 中打开本机生成的初始账号文件。浏览器默认使用本机端口 8000，端口被其他程序占用时会选择空闲端口；以启动窗口显示为准。停止服务按 Ctrl+C，再次双击继续试用。

详细步骤见 `WINDOWS-TRIAL.txt`。该入口不需要安装 npm/pip 依赖，不提供公网访问，不会使用或修改正式账套，也不会把密码放进分发包。程序必须运行，不能直接用浏览器打开 `static/index.html`。Windows 批处理启动本身需在 Windows 上确认，本仓库的业务和浏览器测试在 Linux Chromium 下运行。

## 启动

在已有 checkout 中工作；云任务已隔离，无需额外建立 Git worktree。

```bash
cd /workspace/codex-workplace
# 体验演示账套（含虚构资料、期初库存和销售订单）
python3 server.py --demo --data-dir .data/demo --port 8000
```

服务默认仅监听本机 `127.0.0.1:8000`。健康检查：

```bash
curl --fail http://127.0.0.1:8000/api/health
```

创建独立空白账套，请使用另一数据目录，并且不加 `--demo`：

```bash
python3 server.py --data-dir .data/company --port 8000
```

同一端口只能运行一个服务，先停止原服务。演示和正式数据互不共享，切勿把演示数据当作真实库存。首次启动会初始化数据库及四个随机密码账号：

| 账号 | 人员建议 | 可执行的操作 |
| --- | --- | --- |
| admin | 老板 / 管理员 | 全部业务、物料资料和 BOM |
| sales | 业务人员 | 客户、供应商、销售、采购、收付款 |
| warehouse | 仓库人员 | 期初建账、收货、发货 |
| production | 生产负责人 | 创建工单、领料、工序报工、完工 |

初始密码仅保存在所选数据目录的 `initial-accounts.txt` 中，权限为仅文件所有者可读写；服务日志不会打印密码。由管理员安全分发，首次登录后使用右上角“修改密码”。密码变更会使该账号所有会话失效，旧密码文件不自动更新。所有账号目前都可查看经营数据，权限控制的是写入操作，不提供财务数据隔离。

企业内网使用可指定 `--host 0.0.0.0`，需自行配置网络访问权限。正式部署应使用有 TLS 的反向代理，并加 `--secure-cookie`，配置进程守护、持久化数据目录和定时异机备份。内置 HTTP 服务供开发与小规模验证使用，本仓库没有自动部署到公网。

## 已实现的业务流程

### 自产产品

1. 管理员在“基础资料”录入原材料和成品、单位、安全库存、参考价格，维护客户与供应商。
2. 在“生产 BOM”按 **生产 1 单位成品所需原料数量** 维护用量。例如 1 件成品用 1.25 米面料、4 米背胶。可更新相同成品和原料组合的用量。
3. 仓库通过“期初入库”登记上线前真实库存，填写批次及单位成本；后续收货必须走采购单。
4. 业务创建销售订单。生产负责人从销售单安排生产，或创建不关联订单的备货工单。
5. 工单冻结创建时的 BOM 用量；“待领料需求汇总”显示已建工单的原料需求及缺料数量。缺料时采购补充。
6. 仓库采购收货登记批次，生产负责人整单领料；领料按批次入库顺序先进先出，任何原料不足则整笔回滚。
7. 生产负责人逐工序报工。全部工序（含检验）完成后，登记加工费用总额和成品批号，完工入库。
8. 仓库按销售单整单发货，扣减成品库存；业务按订单登记收款。

### 代理贸易（买断再销售）

1. 录入“贸易商品”，创建供应商采购单。
2. 仓库收货并登记供应商批次和采购成本。
3. 创建该贸易商品的销售订单，直接发货，无需 BOM 和生产工单。
4. 登记采购付款、销售收款；“收支与成本”分别汇总自产产品与代理贸易的已发货毛利。

### 账务及追溯口径

- 单仓库；货币人民币；金额支持 2 位小数，数量支持 3 位小数，经营日期按北京时间处理。
- 数量以千分单位整数、金额以分存储；BOM 需求向上取到千分单位。
- 材料按实际批次成本计算。成品单位成本 =（材料成本 + 手工登记的加工费用）÷ 完工数量，保留至分；会有舍入差异。
- 销售毛利 = 已发货销售金额 − 对应批次出库成本，未计税费与其他经营费用；属于管理口径，不是财务净利润。
- “销售 / 采购未结余额”按所有订单合同金额扣减已登记收付款，**包含尚未发货 / 收货的订单**，不是按发票确认的会计应收应付。
- 库存仅由期初入库、采购收货、生产领料、完工入库和销售发货变动。数据库事务防止重复收货、重复发货和并发超卖。
- 批次追溯展示关联工单的原料、成品及成品发货流水。多个订单可能共享批次，不提供单件序列号或逐件精确分配追踪。
- 业务动作记录操作人、时间和单据编号；不提供删除或直接改库存的功能。

## 第一版边界

当前每张销售 / 采购单只有一个物料行，整单收货、整单发货、整单领料和整单完工；需要分批可先拆单。不提供库存预留、多仓库、盘点调整、退料、销售 / 采购退货、报废、返工、部分合格入库、订单取消与冲销、BOM 删除与版本审批、物料资料编辑、发票和总账核算、Excel 导入导出、自动排产、扫码或设备联网。

工序状态代表人工确认完成，不包含详细产能、分人员工时报工或检验指标。演示资料不是企业的真实产品。正式投入业务前，应先确定退货、损耗和库存调整流程，以及资料录错后的更正机制，再扩展功能。

## 备份与恢复

使用 SQLite 在线备份接口，不能在服务运行时只复制 `.sqlite3` 文件而遗漏 WAL。以下命令不会覆盖已有备份：

```bash
mkdir -p .data/backups
python3 backup.py .data/company/erp.sqlite3 .data/backups/company-2026-11-01.sqlite3
```

备份包含账号密码哈希和全部业务数据，须限制访问并定期保存到另一台机器；备份会清除登录会话，恢复后需重新登录。云环境快照不能代替业务定时备份。

恢复时先停止服务，将备份复制到一个**新的空目录**并命名为 `erp.sqlite3`，再将 `--data-dir` 指向该目录启动。不要覆盖正在使用的数据库，也不要把旧目录的 `-wal`、`-shm` 文件混进新目录。新目录启动会保留备份中的账号和密码，不会生成新账号文件。先核对余额、工单和库存流水，再切换使用。

## 账号说明和手机端使用

账号帮助已内置在网站 `/help` 页面；登录页面点“账号与手机使用帮助”，无需登录即可阅读。聊天中的 `/workspace/...` 文件链接并非网站地址，打不开时不用重复点击。

账号分别是：`admin`（管理员）、`sales`（业务）、`warehouse`（仓库）、`production`（生产）。四个账号没有通用密码；由部署管理员从对应账套的数据目录安全分发初始密码。若密码已丢失，服务器管理员可在交互式终端重置，不需要提供旧密码，也不会改变业务数据：

```bash
cd /workspace/codex-workplace
python3 manage_accounts.py --data-dir .data/company reset admin
```

新密码只通过终端隐藏输入，不能通过命令行参数、聊天或管道传入。该操作会使指定账号全部会话失效并记入日志；不影响其他账号会话。请选对数据目录，工具不会创建新数据库。示例 `company` 是正式账套目录；演示账套使用 `.data/demo`。

手机端的订单、工单、库存、成本表会显示为卡片，按钮适合触摸操作；权限及业务检查与电脑端相同。Android Chrome 或 iPhone Safari 可通过浏览器菜单“添加到主屏幕”，仍需联网使用，不支持离线录单。主屏幕入口及安装提示的可用性取决于浏览器和 HTTPS 配置。

### 公司与外出都使用的部署建议

推荐阿里云或腾讯云入门云服务器，初期可从 **2 核 / 4GB 内存、40GB 以上持久化磁盘** 起步，四个人共用一套数据库；是否需要升级应以实际业务数据及使用情况验证。另购一个域名，配置 HTTPS 反向代理、仅开放必要入口、进程守护和每日异机备份。公网访问 ERP 时服务端使用 `--secure-cookie`，只允许通过 HTTPS 登录。

公司 Wi-Fi 和手机流量都通过**同一个 HTTPS 域名**访问，避免建立两套账而不同步。中国内地服务器的域名通常需按服务商要求备案；购买前确认所在地区的备案和网络要求。这里不承诺具体价格或免费额度。

云环境“发布”只是发布开发环境版本，**没有自动购买服务器、注册域名或发布 ERP 网站**。目前还没有可供手机访问的公网 ERP 网址。本轮仅准备代码和本地验证；实际部署需确定服务器、域名和受支持的安全管理访问方式，不要在聊天中发送密码或密钥。
